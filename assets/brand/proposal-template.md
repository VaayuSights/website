# Proposal template

Fill in everything in `[ brackets ]`, delete what does not apply, then ask
for it to be rendered as a branded PDF.

Three shapes cover almost everything we sell:

| Shape | When |
|---|---|
| **A — Analysis only** | the client already has imagery. Our default |
| **B — Capture and analysis** | no usable data; capture arranged through a partner |
| **C — Cleaning** | aerial cleaning, our own crews |

Keep it short. A two-page proposal that states scope, deliverables and price
plainly beats a twelve-page document nobody reads to the end.

---

## 1. Cover

```
Proposal for [ CLIENT NAME ]
[ ENGAGEMENT TITLE — e.g. Thermal analysis, 12 MW solar plant ]

Prepared for   [ CONTACT NAME, ROLE ]
Date           [ DATE ]
Valid until    [ DATE + 30 days ]
Reference      VS-[ YYYY ]-[ NN ]
```

---

## 2. What you asked for

Two or three sentences, in their words, not ours. Showing we listened is
worth more here than showing we are clever.

> [ e.g. You have a 12 MW rooftop array near Chakan and a thermal survey
> flown in October that has not been analysed. You want to know which
> modules are underperforming before the next maintenance window in
> January. ]

---

## 3. What we will do

Plain steps. No jargon the client did not use first.

```
1. [ Ingest and quality-check the supplied survey ]
2. [ Radiometric analysis across all frames ]
3. [ Defect detection and classification by severity ]
4. [ Engineer review of every finding ]
5. [ Module-level defect map keyed to your plant layout ]
6. [ Report and walkthrough call ]
```

For shape B, add the capture step and say plainly how it is run:

> Capture is flown by a vetted partner operator working to our capture
> specification, so the data arrives fit for analysis. We scope the mission,
> brief the operator and quality-check what comes back.

---

## 4. What you receive

Be specific. This section is what they compare against other quotes.

```
- [ Module-level defect map, keyed to plant layout ]
- [ Ranked defect list: location, type, severity, recommended action ]
- [ Annotated thermal frames for every flagged module ]
- [ Summary report, PDF ]
- [ Raw processed outputs: orthomosaic GeoTIFF / point cloud LAS ]
- [ One walkthrough call with your engineering team ]
```

---

## 5. What we need from you

Listing this prevents the commonest cause of delay.

```
- [ The survey imagery, with flight logs if available ]
- [ Plant layout or string diagram ]
- [ A named technical contact for questions ]
- [ Site access dates, if capture is in scope ]
```

---

## 6. Timeline

```
Data received        day 0
Draft findings       day [ N ]
Review call          day [ N ]
Final delivery       day [ N ]
```

Quote working days and leave yourself margin. Delivering early is free
goodwill; delivering late on a first engagement is expensive.

---

## 7. Commercial

```
[ SCOPE LINE ]                               INR [ AMOUNT ]
[ OPTIONAL EXTRA ]                           INR [ AMOUNT ]
                                             ─────────────
Total                                        INR [ AMOUNT ]
                                             plus GST, if applicable
```

**Structures that work.** Per asset for inspection; per MW for solar; per
km for linear assets; per hectare for mapping; per day for cleaning; a
quarterly retainer for repeat surveys, which is the one worth steering
toward because it makes the trend analysis valuable and the revenue
predictable.

**Payment.** [ e.g. 50% to begin, 50% on delivery. Net 15 days. ]

---

## 8. Assumptions and exclusions

Protects both sides. Be specific rather than defensive.

```
- [ Pricing assumes imagery meets the capture spec in Appendix A ]
- [ A re-fly, if the supplied data cannot support the deliverables,
    is quoted separately ]
- [ Excludes physical repair, electrical testing, certification ]
- [ Excludes travel outside [ AREA ] ]
- [ Deliverables in English ]
```

---

## 9. Confidentiality and ownership

```
Your data remains yours. We process it for this engagement only, do not
share it, and will delete or return it on request after delivery.

Deliverables become yours on final payment.

We would like to reference this work as an anonymised case study — no
client name, no location, no identifying detail. Tick to decline: [ ]
```

That last line is worth keeping. Most clients agree when it is anonymous
and asked up front, and it is how the website eventually carries real work
instead of stock photography.

## Before sending — check

- Is the price structured per asset, MW, km or day, not a round guess?
- Does every deliverable name a format the client can open?
- Have we promised a date we can hold, with margin?
- Have we claimed nothing we have not done?
- Is capture described as partner-run where it applies?
- Is it under three pages?
